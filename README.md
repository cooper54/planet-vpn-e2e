# Planet VPN — E2E-тесты покупки Personal VPN

Автотесты процесса покупки Personal VPN на англоязычной версии сайта
[personal.freevpnplanet.com](https://personal.freevpnplanet.com/):
выбор страны, валюты и тарифа → выбор способа оплаты → переход на страницу платёжной системы.

**Стек:** Playwright Test + TypeScript, паттерн Page Object, data-driven тесты, GitHub Actions.

---

## Быстрый старт

Нужен **Node.js 18+** (проверить: `node --version`).

```bash
git clone https://github.com/cooper54/planet-vpn-e2e.git
cd planet-vpn-e2e
npm ci                          # зависимости строго по package-lock.json
npx playwright install chromium # браузер для тестов
```

### Запуск

```bash
npx playwright test                                # все тесты
npx playwright test tests/purchase.spec.ts         # только покупки (14 тестов)
npx playwright test tests/payment-methods.spec.ts  # только негативные (5 тестов, без заказов у провайдеров)
npx playwright test -g "RUB"                       # тесты, в названии которых есть "RUB"
npx playwright test --ui                           # интерактивный режим с пошаговыми скриншотами
npx playwright test --list                         # список тестов без запуска браузера
npx playwright show-report                         # HTML-отчёт последнего прогона
npx eslint .                                       # линтер: ESLint + правила Playwright
npx prettier --check .                             # проверка форматирования
```

Локально браузер открывается в видимом режиме, в CI (`CI=true`) — в фоновом.

### Почта для оформления заказа

Каждый тест создаёт заказ с уникальным адресом вида `planet.vpn.qa+<timestamp>@gmail.com`.
Можно подставить свою почту через переменную окружения:

```bash
TEST_EMAIL=me@gmail.com npx playwright test          # bash
$env:TEST_EMAIL="me@gmail.com"; npx playwright test  # PowerShell
```

> Домен `example.com` сайт отклоняет (страница `/payment/failed/`), поэтому для позитивных
> сценариев нужен реальный почтовый домен. Это поведение отдельно проверяется негативным тестом.

## Что покрыто

### Позитивные сценарии — `tests/purchase.spec.ts` (14 тестов)

Полная матрица **тариф × валюта × доступный способ оплаты**:

| Валюта | Способы оплаты                                      | Тарифы          | Тестов |
| ------ | --------------------------------------------------- | --------------- | ------ |
| USD    | Credit Card (Stripe), Cryptocurrency (Heleket)      | 1 month, 1 year | 4      |
| EUR    | Credit Card (Stripe), Cryptocurrency (Heleket)      | 1 month, 1 year | 4      |
| RUB    | Credit Card (Stripe), Cryptocurrency (Heleket), СБП | 1 month, 1 year | 6      |

Каждый тест проверяет не только факт перехода, но и целостность данных по всему пути:

1. **Главная:** выбранные страна и валюта применились к форме, цена тарифа совпадает с ожидаемой.
2. **Страница выбора оплаты:** открылась, и тариф, валюта и страна дошли до неё без искажений (параметры URL).
3. **Платёжная система:** редирект на нужного провайдера, на его странице — правильная сумма.

| Провайдер | Что проверяется                                                                                                                |
| --------- | ------------------------------------------------------------------------------------------------------------------------------ |
| Stripe    | домен `checkout.stripe.com`, итоговая сумма заказа, email покупателя                                                           |
| Heleket   | домен `pay.heleket.com`, сумма к оплате                                                                                        |
| СБП       | домен `pay.x-hub.online` или `qr.nspk.ru` (сайт использует оба); сумма — только на x-hub, страница НСПК показывает лишь QR-код |

### Негативные сценарии — `tests/payment-methods.spec.ts` (5 тестов)

| Сценарий                                        | Ожидаемое поведение                                                                            |
| ----------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| Валюта USD                                      | способ оплаты СБП не предлагается (он доступен только для RUB)                                 |
| Валюта EUR                                      | способ оплаты СБП не предлагается                                                              |
| Pay без согласия с условиями                    | форма не отправляется, чекбокс помечен браузером как `:invalid`                                |
| Email в неверном формате (`not-an-email`)       | форма шага 1 не отправляется, поле помечено как `:invalid`                                     |
| Email с недоставляемым доменом (`@example.com`) | заказ отклоняется: редирект на `/payment/failed/` со страницей ошибки вместо платёжной системы |

### Почему 14 тестов, а не 168

Тариф на 2 дня вне скоупа ТЗ (только месячная и годовая подписка).

Сумма и платёжная система зависят от **тарифа, валюты и способа оплаты** — эти параметры перебираются полностью.
**Страна** (12 вариантов) на биллинг не влияет, поэтому страны распределены по тем же 14 тестам по кругу:
каждая страна проверяется хотя бы один раз. Полный перебор дал бы 2 × 7 × 12 = 168 тестов —
в 12 раз больше реальных заказов у платёжных провайдеров без выигрыша в покрытии биллинга.

Оплата **не проводится**: тест останавливается на странице платёжной системы, как и требует ТЗ.

## Структура проекта

```
src/
  data/                  # факты о сайте — что тестируем
    plans.ts             #   тарифы и ожидаемые цены в USD / EUR / RUB
    locations.ts         #   страны (коды как на сайте)
    paymentMethods.ts    #   способы оплаты: в каких валютах доступны, куда ведут
  pages/                 # Page Object — как взаимодействовать со страницами
    HomePage.ts          #   шаг 1: страна, валюта, тариф, email
    PaymentMethodPage.ts #   шаг 2: способ оплаты, согласие с условиями
    PaymentGatewayPage.ts#   проверки на страницах Stripe / Heleket / СБП
  utils/
    testData.ts          #   уникальный email, гибкий шаблон суммы
  fixtures.ts            # страницы приходят в тест готовыми, как встроенная `page`
tests/
  purchase.spec.ts       # позитивные сценарии (матрица из данных)
  payment-methods.spec.ts# негативные сценарии (способы оплаты, согласие, email)
playwright.config.ts
.github/workflows/playwright.yml
```

## Принятые решения

- **Page Object.** Локаторы и действия собраны в классах страниц; тесты читаются как тест-кейсы
  и не содержат селекторов.
- **Фикстуры вместо `new Page(...)` в каждом тесте.** Расширенный `test` из `src/fixtures.ts`
  отдаёт `homePage`, `paymentMethodPage`, `gatewayPage` готовыми.
- **Data-driven.** Тесты генерируются циклами из `src/data`, без копирования кода.
- **Локаторы по `qa-*` id.** На сайте есть тестовые атрибуты (`#qa-radio-offer-1-month`,
  `#qa-select-currency-eur`, `#qa-btn-submit-step1` и т.д.) — они не зависят от текста, цены и вёрстки.
  На внешних страницах — `data-testid` Stripe и текст.
- **Клик по `label`, а не по `input`.** Радиокнопки и чекбокс на сайте кастомные: настоящий `input`
  скрыт, поэтому клик идёт туда же, куда кликает пользователь.
- **Каждое действие подтверждается проверкой:** после выбора валюты — атрибут формы, после выбора
  тарифа — `toBeChecked()`. Тест падает там, где сломалось, а не на шаг позже.
- **Без `sleep`/`waitForTimeout`.** Только ожидание состояния через `expect`.
- **Негативные проверки отсутствия — через `toHaveCount(0)`**, а не `not.toBeVisible()`: важно,
  что способа оплаты нет на странице вообще, а не что он спрятан.
- **Устойчивые проверки сумм.** Платёжки форматируют сумму по-разному (`$6.90`, `6,90 $`, `2 990 ₽`),
  поэтому сумма сверяется шаблоном, допускающим разделители, а не точной строкой.
- **Увеличенные таймауты только там, где нужно** — для редиректа на внешние платёжные страницы,
  которые грузятся заметно дольше сайта.
- **Мало потоков и только Chromium.** Каждый тест создаёт реальный заказ у провайдера; параллельный
  запуск в нескольких браузерах умножил бы нагрузку на продакшен.
- **`locale: 'en-US'`.** ТЗ — англоязычная версия; язык браузера влияет и на страницы Stripe/Heleket.
- **Артефакты при падении:** скриншот и трейс (`npx playwright show-trace <file>`).
- **ESLint + Prettier.** ESLint с правилами `typescript-eslint` и `eslint-plugin-playwright` (ловит
  забытый `await`, `test.only`, тесты без проверок), Prettier — единый стиль. Оба запускаются в CI
  до тестов, поэтому ошибка оформления или линтера видна за секунды.

## CI

GitHub Actions (`.github/workflows/playwright.yml`) запускает тесты на каждый push и pull request
в `main`. HTML-отчёт сохраняется как артефакт прогона (вкладка **Actions → прогон → Artifacts**).
